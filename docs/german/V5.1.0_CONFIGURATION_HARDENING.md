## 📊 Executive Summary

Wir **perfektionieren die Konfigurationsverwaltung** des KI-Agenten. Das Onboarding soll **100% fehlertolerant** sein und die Daten sollen **persistent, validiert und gesichert** gespeichert werden.

**Warum wichtig?**
- Nutzer füllen Settings aus → Daten werden **NICHT** gespeichert ⚠️
- Keine Validierung → API-Keys mit Tippfehler speichern ⚠️
- Keine Tests → Services funktionieren nicht, obwohl Config "ok" aussieht ⚠️
- Shell-Script nicht vollständig → connection.json hat fehlende Felder ⚠️

**Lösung:** Robuste System mit Validierung, Tests und persistenter Speicherung.

### Phase 2: Feldvalidierung (Backend) ⚙️ STARTING NOW

**Was:** Backend validiert alle Eingaben VOR dem Speichern

**Zu implementieren:**

```typescript
// backend/services/configValidator.ts (CREATED ✅)
configValidator.validate(credentials) → ValidationResult
// Returns: { isValid, errors: [], warnings: [] }
```

**Validierungsregeln:**

```
URLs:
  ✓ Muss mit http:// oder https:// beginnen
  ✓ Keine relativen URLs
  ✓ Hostname resolverbar (optional)

APIs:
  ✓ Consumer Keys: Länge ≥20, keine Platzhalter
  ✓ API Keys: Format (sk-..., ck_...), keine Platzhalter
  ✓ OAuth Tokens: Länge ≥10, keine Platzhalter

Email:
  ✓ Valid RFC 5322 Format
  ✓ Nicht leer wenn SMTP konfiguriert

Port Numbers:
  ✓ 0-65535
  ✓ Keine Strings

Timeouts:
  ✓ Positive Integer
  ✓ Max 120000ms (2 Minuten)

Confidence Levels (ML):
  ✓ 0.0-1.0 Range
  ✓ Numerisch
```

**Integration in Routes:**

```typescript
// backend/routes/app/api/settings/connection.ts
fastify.post('/connection', async (request, reply) => {
  const credentials = request.body;
  
  // 1. VALIDIERUNG
  const validation = configValidator.validate(credentials);
  if (!validation.isValid) {
    return reply.status(400).send({
      success: false,
      errors: validation.errors,
      message: "Validation failed"
    });
  }
  
  // 2. WARNINGS warnen (aber nicht blocken)
  if (validation.warnings.length > 0) {
    console.warn("⚠️ Config Warnings:", validation.warnings);
  }
  
  // 3. SPEICHERN
  await saveConfig(credentials);
  
  return { success: true, message: "Config saved" };
});
```

### Phase 6: API Key Masking ⚙️ NEXT

**Problem:**
```typescript
// Heute:

  openaiApiKey: "sk-proj-xxxxx...xxxxx"  // ← Sitzt im Frontend State
}
// If user öffnet DevTools: Kann Key sehen ⚠️

// Später wenn Frontend aktualisiert:
if (apiKey.startsWith('****')) {
  return oldValue;  // Nutzer kann Key nie ändern! ❌
}
```

**Lösung: Masking nur im Frontend**

```typescript
// Backend: Speichert Keys wie normal
saveConfig(credentials);
// → connection.json hat echte Keys

// Backend: Beim Laden maskiert für UI
response.credentials = {
  openaiApiKey: "sk-proj-****...****",  // ← Maskiert
  // Nutzer kann diese "****" value nicht speichern
};

// Frontend: Kennt dass es maskiert ist
if (value.startsWith("****")) {
  // Verwende old value nicht, hole fresh value vom Backend
  // ODER: Nutzer muss vollständigen neuen Key eingeben
}
```

## 🎯 Warum das wichtig ist

**Heute (v5.0.0):**
```
Nutzer macht Onboarding
  ↓
Füllt Settings aus
  ↓
Speichert
  ↓
... nichts passiert (silent failure)
  ↓
Agent funktioniert nicht
  ↓
Nutzer ist verwirrt 😞
```

**Nachher (v5.1.0):**
```
Nutzer macht Onboarding
  ↓
Füllt Settings aus
  ↓
Backend validiert (Fehler? → Sofort Feedback!)
  ↓
Test Connection durchlaufen (Alle Services OK?)
  ↓
Speichern erfolgreich
  ↓
Refresh → Alles ist noch da ✅
  ↓
Agent funktioniert sofort 🎉
```
